## 问题现象与根因
- 解密预览页原始文件名乱码：旧版 Dart 备用加密实现使用 `codeUnits` 写入文件名，非 ASCII 被截断为 8 位；解析时又用 `String.fromCharCodes`，导致预览显示不正确。保存到书架后正常，通常因为显示用的是条目标题或路径基名而非头部原始名。
- 从书架进入阅读后返回到 ViewerScreen：栈上仍保留了 ViewerScreen 这一中间页，阅读页关闭后回到它，再次返回才到书架。
- 加密/解密卡顿：Rust 同步 FFI/大文件 IO/JSON 解析导致主线程长时间无反馈；进度条只在少数节点更新，看起来“卡住”。

## 修复方案（文件名）
1. 统一用 UTF‑8 编码/解码文件名（新生成文件）：加密写头时用 `utf8.encode`，解析时用 `utf8.decode(allowMalformed: true)`；FRB 路径保持 UTF‑8 原样。
2. 旧文件容错显示：在 ViewerScreen 中对解析出的文件名做健壮处理，检测包含大量替换符或高位字节时，优先显示 `path.basename(_selectedFile!.path)` 作为原始文件名预览。
3. 在解密结果赋值和 AppBar/信息块展示处，统一使用 `path.basename`，避免分隔符导致异常。

## 导航优化（书架返回）
1. 识别来源：ViewerScreen 已有 `initialFile` 参数，视为来自书架入口。
2. 内容页导航改为替换：
   - 对小说/漫画/富小说：将当前 `Navigator.push` 改为 `Navigator.pushReplacement`（或 `pushAndRemoveUntil` 到 `/library`），阅读页关闭时直接回到书架。
   - 若是图片/纯文本在 ViewerScreen 内部展示：当 `initialFile != null` 时，返回按钮执行 `Navigator.pop(context)` 直接回到书架；或用 `WillPopScope`/自定义 `leading` 覆盖返回行为。
3. 书架点击漫画/富小说时也可直接用 `pushReplacement` 打开 ViewerScreen，进一步减少中间页残留。

## 性能与进度优化
1. 确认所有加密/解密/头解析走 FRB 异步 API（NormalTask），避免阻塞 UI。
2. UI 渲染让步：在进度阶段设置 `setState` 后插入一次 `await Future.delayed(const Duration(milliseconds: 16))` 保证下一帧绘制。
3. 大型 JSON/容器解析放到后台 isolate：
   - 小说 JSON `jsonDecode`、漫画/富小说容器 `unpack*Container` 放入 `compute`/`Isolate.run`。
4. 可选增强：Rust 侧加入分步进度回调（加盐、派生密钥、加/解密、写入），通过 FRB Stream 推送到 Flutter 实时更新。

## 变更点清单
- ViewerScreen：
  - 解析/解密后对文件名做容错 `decode + basename`，统一展示。
  - 来源为书架时，改用 `pushReplacement` 打开阅读页；图片/文本时覆盖返回行为直达书架。
- BookshelfScreen：
  - 点击漫画/富小说时，改为 `pushReplacement` 打开 ViewerScreen（可选）。
- 备用加密实现（仅当 FRB 不可用时）：确保 UTF‑8 写入/解析；已对旧文件通过容错显示处理。
- 进度与性能：插入 UI 让步；将重算任务迁移到 isolate；后续可加 Rust 进度流。
