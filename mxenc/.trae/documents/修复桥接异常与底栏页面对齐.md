## 问题定位
- Flutter Rust Bridge 内容哈希不一致：Dart 端 `rustContentHash` 为 `-291292710`（lib/bridge_generated/frb_generated.dart:66），运行时报错指向 Rust 端为 `1338505872`，说明桥接代码未同步或热重启后未重新编译 Rust。
- 生成文件被手改且未实现：`lib/bridge_generated/crypto.dart` 多处 `TODO/UnimplementedError`（例如行42-54、58-60、12-17），导致加密/解密/指纹功能不可用。
- 底栏与页面不匹配：底栏 3 个目的地（lib/main.dart:95-108），`IndexedStack` 仅 2 个子项（lib/main.dart:78-87），切到“我的”会越界。
- 无效图标：`Icons.shelves` 不是标准 Material 图标（lib/main.dart:101）。
- 未注册路由：加密页跳转 `'/permission'`（lib/screens/encrypt_screen.dart:49-51、67-71），但 `MaterialApp` 未配置该路由（lib/main.dart:24-31）。

## 修复方案
1. 清理与重新编译 Rust
- 在 `rust_core` 目录执行：
  - `cargo clean`
  - `cargo build --release`
- 确认生成 `rust_core/target/release/mxenc_core.dll`（Windows）。

2. 重新生成桥接代码（不要手动改 `lib/bridge_generated/*`）
- 若使用 FRB v2 自动生成：重新编译 Rust 后完整重启 Flutter 应用（不使用热重启）。
- 若未自动生成，使用 CLI 重新生成：
  - 安装：`cargo install flutter_rust_bridge_codegen`
  - 生成：`flutter_rust_bridge_codegen generate --rust-input rust_core/src/lib.rs --dart-output lib/bridge_generated/`
- 目标：生成可用的 Dart 绑定函数（`encrypt_file / decrypt_file / parse_mxenc_header / generate_device_fingerprint` 等）替换掉当前占位实现。

3. Dart 端初始化与加载
- 启动前执行 `flutter clean`，再 `flutter pub get`。
- 完整重启应用以加载新的 Rust 动态库和生成代码。

4. UI 与导航修正
- 替换无效图标：`Icons.shelves` → `Icons.library_books`。
- 为底栏添加第三个页面占位（“我的”），使 `IndexedStack` 子项数量与底栏一致，避免越界。
- 在 `MaterialApp` 配置 `routes` 或 `onGenerateRoute`，注册 `'/permission'`，提供基础占位页以避免导航报错。

5. 调用适配
- 将 `rust_bridge.dart` 的调用从占位类 `MxEncFile` 切换到实际生成的函数接口（例如 `encrypt_file`、`decrypt_file`、`parse_mxenc_header`、`generate_device_fingerprint`）。
- 保持 `RustLib.init` 的默认 `ExternalLibraryLoaderConfig`（lib/bridge_generated/frb_generated.dart:68-73）指向 `rust_core/target/release/`。

## 验证步骤
- Windows 端运行：切换底栏三页无错误；“我的”显示占位内容。
- 加密流程：选择任意文件 → 加密成功，生成 `*.mxenc`。
- 解密流程：选择 `.mxenc` → 输入密码 → 正常显示文本/图片；保存到书架提示正常。
- 设备指纹：`ViewerScreen` 水印显示非占位符（来源于 `generate_device_fingerprint`）。
